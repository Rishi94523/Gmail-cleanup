# Nebius streaming benchmark — October 30, 2026

Ten synthetic email records per request, three consecutive identical requests per model, with at most one request per model in flight (two total). No Gmail or database access. Uses Inboxclean's production `batchPromptMessages` and `chatRequest` builders after shared-context extraction. Super uses medium reasoning; Ultra uses provider-default reasoning. Both retain thinking, temperature 0, 50,000 maximum output tokens and the 120-second deadline.

Run with `npm run ai:benchmark`. Detailed local report: `data/nebius-benchmark-2026-10-30T11-00-36-456Z.json` (ignored). Node.js client on the development machine, not Cloud Run; Super endpoint us-north1, Ultra endpoint us-central1. Network, region and replica placement affect these results.

Median generation speed: Super **366.60 tok/s**, Ultra **434.32 tok/s**. Median full-request duration: Super **11.08 seconds**, Ultra **12.00 seconds**. All six responses finished normally and supplied exactly one structurally valid action per email. This validation is not an accuracy evaluation or permission to apply the synthetic decisions to real mail.

Generation TPS is provider-reported completion tokens divided by elapsed time between the first and last text/reasoning deltas. It includes reasoning tokens and is approximate because streaming chunks can batch tokens. End-to-end TPS divides the same token count by the entire request duration. First-token latency includes reasoning; first visible JSON is reported separately.

This is a small observational sample, not a controlled comparison of identical reasoning effort, a concurrency/load test, or a measurement of Gmail cleanup duration. A preliminary six-request run with a different prompt layout gave Super 407 tok/s and Ultra 298 tok/s (medians), illustrating substantial variation; those values should not be directly compared to the optimized layout as an isolated causal effect. Ultra stays selected; no model or reasoning setting was changed by this benchmark.

## Caching

[Nebius documents automatic, best-effort prefix caching](https://docs.tokenfactory.nebius.com/cached-tokens). No cache flag, explicit marker, or TTL was added. Stable system instructions come first, then shared account context, then per-email data. Only fields present and identical in every batch item are deduplicated; individual preferences and exceptions stay attached to their email. Discovery notes and clocks were moved out of system instructions, and preference interpretation puts stable topics/preferences before variable replies.

Super's two repeat calls reported 2176 cached tokens each (47.4% of each input). Ultra reported zero on all three calls. Repeated prompts do not guarantee hits; these observations cannot establish that Ultra never caches. Cached-input billing depends on each model's current pricing and actual reported hits. The application already logs cache counts without prompts or email contents.
